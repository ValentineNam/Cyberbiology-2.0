# Инструкции агенту

- Проект переписывается с нуля для локальной лаборатории. `legacy/` и исходный аудит не изменять; старый код — источник механик, не эталон поведения.
- Перед работой читать [продукт](docs/product.md), [правила](docs/rules.md), [архитектуру](docs/architecture.md) и выбранную задачу из `docs/tasks/`. Реестр: [features](docs/features.md); порядок работ: [roadmap](docs/roadmap.md).
- Нормативны только разделы с принятыми решениями и принятые ADR. Предложения, открытые вопросы и условия будущих задач не считать утверждением механик. При противоречии новых указаний пользователя и документов обновить документы.
- Выполнять только текущую задачу. Сначала кратко описать план; не добавлять зависимости, API или интерфейс вне её объёма. Неопределённое правило согласовать до реализации зависящего от него поведения.
- Сохранять независимость ядра от транспорта и UI. Случайность мира направлять через его RNG; не менять правила ради прохождения проверок.
- Проверять наблюдаемое поведение и инварианты; сообщать реально выполненные проверки. Не заявлять производительность без измерений.
- При изменении правил обновлять `docs/rules.md` и при существенном решении ADR. Обновлять статус функции только по подтверждённой приёмке; завершать задачу после выполнения её критериев.

Решение о реактивной программе: [ADR 0001](docs/decisions/0001-reactive-genome.md). Аудит [Cyberbiology-2.0-audit-spec.md](Cyberbiology-2.0-audit-spec.md) — справочный документ с неутверждёнными предложениями.
