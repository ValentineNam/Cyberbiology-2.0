# Cyberbiology 2.0

Локальная лаборатория эволюции программируемых организмов. Главный приоритет — изучение архитектуры и разработки с Codex. Проект переписывается с нуля; `legacy/` и исходный аудит сохраняются без изменений.

Завершены задачи 001–004: технический мир, независимая VM, ресурсные действия и жизненный цикл с растениями, рождениями, происхождением и мутациями. F01–F08 выполнены. API, интерфейс и сохранения ещё не созданы. Используется установленный Python 3.13.0 и стандартная библиотека, включая unittest; зависимости не устанавливались.

## Запуск и проверки

Из корня проекта, без установки:

```sh
python3 --version
python3 -m unittest discover -s tests -v
python3 -m core
python3 -m core.vm_example
python3 -m core.biology_example
python3 -m core.lifecycle_example
python3 -m core.lifecycle_example --long
git diff --check
```

Проверено: 80 тестов, OK. Прежние примеры работают с текущими правилами; ресурсный пример выполняет пять тиков с R=4096. Новый пример — 140 тиков с известным геномом PHOTOSYNTHESIS и всеми тремя растениями, выводом метрик и проверкой R=30000 на каждом шаге. Параметры этого сценария — примеры, не новые правила баланса.

`--long` выполняет два одинаковых прогона по 2000 тиков и сравнивает сущности, резерв, tick, следующий ID, события и состояние RNG. Фактический итог: резерв 0, R=30000; 1 рождение и 2 смерти организмов, 800 рождений и 760 смертей растений, 0 мутаций. Остались 43 grass и 2 останков, организмы вымерли. Это проверка воспроизводимости и бюджета; устойчивую эволюцию или качество баланса один сценарий не доказывает.

## Технический мир и VM

[World](core/world.py) управляет координатами и уникальными ID, не знает ресурсов. `get_at` возвращает None для пустоты и вызывает OutOfBoundsError за краем; `get(id)` возвращает None для отсутствующего ID. Размещение в занятую клетку запрещено (OccupiedCellError), изменение отсутствующего ID — UnknownEntityError. Типы/размеры валидируются. Ошибочные операции не меняют состояние, следующий ID или RNG. Техническое перемещение в собственную клетку разрешено.

`World.step(update=None, order=None)` сохраняет возрастающий порядок по умолчанию; явный order копируется и проверяется на уникальные существующие ID. `World.run_tick(callback)` даёт общую границу составного тика. Вложенные тики запрещены; успешное завершение увеличивает tick один раз. Исключение не откатывает уже выполненные эффекты и не увеличивает tick.

[VM](core/vm.py) принимает геном 32×0–31 без bool, сенсоры, исполнитель и RNG. Каждый вызов начинается с PC=0, бюджетом 16 и без памяти. Полная валидация предшествует эффектам; VM не изменяет геном. Результат: `ExecutionResult(instructions_executed, reason, last_pc)` — последний исполненный адрес. Причины: terminal_action, budget_exhausted, adapter_stopped.

Необязательный `is_active` проверяется после каждого действия; False останавливает VM до следующей инструкции и до обычного терминального завершения. При ручном подключении `OrganismAdapter` передавать `is_active=adapter.is_active`; BiologicalWorld.step делает это автоматически. Сенсоры возвращают целую категорию 0–5 и bool голода; исполнитель — bool. Исключения адаптеров/callback передаются вызывающему коду, не означают смерть или отказ. Без callback контракт 002 сохранён.

## Биологический слой

[BiologicalWorld](core/biology.py) владеет приватным World, резервом и неизменяемыми ресурсными снимками. Публичной установки запасов или возраста нет. `create_organism` по умолчанию создаёт возраст 0, север, 256 E / 64 M за 512 из резерва; явные начальные запасы валидируются. `create_plant` требует явных запасов в пределах профиля tree/bush/grass. `create_remains` не обрезает запасы. Нехватка резерва — InsufficientReserveError без частичных изменений. Снимки не обновляются автоматически: актуальные записи читать по ID.

`remove` — техническое удаление с возвратом остатка в резерв, без события смерти; `move` — техническое перемещение без цены. `perform` выполняет игровое действие. При смертельной оплате дальнейших эффектов нет: EAT при E=1 не получает ресурс цели. Смерть меняет живой ID на новый ID останков в той же клетке, без возврата ресурсов в резерв; оба нулевых запаса освобождают клетку. Пустые съеденные останки удаляются сразу.

Бюджет R = резерв + Σ(E+4*M) сохраняется при создании, действиях, росте, делении запасов при рождении, смерти и распаде. Последний возвращает остаток в резерв. Обычные операции биологического слоя не открывают обход учёта через внутренний World; прямое изменение приватных полей не поддерживается.

`step` фиксирует все три списка участников: останки по ID → перемешанные растения → перемешанные организмы. Каждая живая фаза перемешивается непосредственно перед выполнением; растения растут до ходов организмов. Возраст растёт один раз, смерть проверяется в установленных фазах и после действий. Дети и новые останки ждут следующего тика. Возвращаются ID/ExecutionResult только организмов, дошедших до VM.

`RulesConfig` хранит принятые параметры и вложенные PlantRules. Для проверок допускаются уменьшенные пределы возраста и вероятности mutation_percent / plant_reproduction_percent от 0 до 100; иной баланс пока отвергается. Весь геном наследуется независимо; мутация при рождении меняет одну любую ячейку. parent_id/founder_id/generation отражают происхождение, а сенсор родства по-прежнему сравнивает геномы.

`metrics` возвращает снимок событий (рождения/смерти организмов и растений, мутации) и численности organisms/tree/bush/grass/remains. Ручное создание не считается рождением. Полноценный инструмент выбора конфигурации и анализа опытов пока не поставлен. Нет многопоточного доступа, отката неуспешного тика, API/UI или сохранений.
