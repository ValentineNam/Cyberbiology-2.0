# Cyberbiology 2.0

Локальная лаборатория эволюции программируемых организмов: пользователь задаёт начальные программы и среду, наблюдает наследование, мутации и конкуренцию за ограниченные ресурсы. Главный приоритет — изучение архитектуры и разработки с Codex.

Проект переписывается с нуля. Реализована итерация 001: независимое ядро мира, проверки и запуск без браузера. Используется доступный Python 3.13.0 и только стандартная библиотека; новые пакеты и версии Python не устанавливались. VM, игровые механики, API и интерфейс ещё не созданы. Планируется отдельный веб-интерфейс; будущий стек ещё не утверждён.

## Запуск и проверки

Из корня проекта, без установки зависимостей:

```sh
python3 --version
python3 -m core
python3 -m unittest discover -s tests -v
git diff --check
```

Проверено на Python 3.13.0: демонстрация создаёт мир 17×11 и выводит три завершённых тика; 12 тестов проходят. Размер, seed и число шагов демонстрации — примеры, не параметры баланса.

## Интерфейс ядра

[core/world.py](core/world.py): `World(width, height, seed=...)`, `place(x, y)`, `get_at(x, y)`, `get(id)`, `remove(id)`, `move(id, x, y)`, `step(update=None)`. Сущности — неизменяемые снимки с `id`, `x`, `y`; `entities` возвращает снимок реестра по ID. После перемещения старый снимок не меняется — актуальную запись получают через `get`.

Пустая клетка и отсутствующий ID при чтении возвращают `None`. Внешняя координата вызывает `OutOfBoundsError`, занятая клетка — `OccupiedCellError`, изменение отсутствующего ID — `UnknownEntityError`. Неверный тип вызывает `TypeError`, неположительный размер — `ValueError`. Отказные операции не меняют состояние, следующий ID или RNG. Перемещение в собственную клетку разрешено без изменения состояния. ID выдаются с 1 и не переиспользуются.

Технический обработчик `update(world, entity)` может изменять мир через его операции. Список ID фиксируется в начале шага; возрастающий порядок временный и требует пересмотра перед питанием и размножением. Вложенный `step` запрещён. Если обработчик выбросил исключение, оно передаётся вызывающему коду, tick не увеличивается, уже выполненные изменения не откатываются. Это синхронный каркас для корректных обработчиков, без многопоточного доступа и транзакционного отката тика.

Случайные выборы выполняются через `world.rng`. Воспроизводимость проверена для одинаковых seed и операций в одной версии реализации; между версиями Python не гарантируется.
