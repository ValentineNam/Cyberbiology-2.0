# Cyberbiology 2.0

Локальная лаборатория эволюции программируемых организмов: пользователь задаёт начальные программы и среду, наблюдает наследование, мутации и конкуренцию за ограниченные ресурсы. Главный приоритет — изучение архитектуры и разработки с Codex.

Проект переписывается с нуля. Реализованы итерации 001–003: независимый мир, управляющая VM и ресурсный биологический слой, проверки и примеры без браузера. Используется доступный Python 3.13.0 и только стандартная библиотека; новые пакеты и версии Python не устанавливались. Реализованы действия и закрытая ресурсная экономика; жизненный цикл, API и интерфейс ещё не созданы. Планируется отдельный веб-интерфейс; будущий стек ещё не утверждён.

## Запуск и проверки

Из корня проекта, без установки зависимостей:

```sh
python3 --version
python3 -m core
python3 -m core.vm_example
python3 -m core.biology_example
python3 -m unittest discover -s tests -v
git diff --check
```

Проверено на Python 3.13.0: демонстрация создаёт мир 17×11 и выводит три завершённых тика; 51 тест проходит (12 для мира, 19 для VM, 20 для биологического слоя и явного порядка). Размер, seed и число шагов демонстрации — примеры, не параметры баланса.

## Интерфейс ядра

[core/world.py](core/world.py): `World(width, height, seed=...)`, `place(x, y)`, `get_at(x, y)`, `get(id)`, `remove(id)`, `move(id, x, y)`, `step(update=None)`. Сущности — неизменяемые снимки с `id`, `x`, `y`; `entities` возвращает снимок реестра по ID. После перемещения старый снимок не меняется — актуальную запись получают через `get`.

Пустая клетка и отсутствующий ID при чтении возвращают `None`. Внешняя координата вызывает `OutOfBoundsError`, занятая клетка — `OccupiedCellError`, изменение отсутствующего ID — `UnknownEntityError`. Неверный тип вызывает `TypeError`, неположительный размер — `ValueError`. Отказные операции не меняют состояние, следующий ID или RNG. Перемещение в собственную клетку разрешено без изменения состояния. ID выдаются с 1 и не переиспользуются.

Технический обработчик `update(world, entity)` может изменять мир через его операции. Список ID фиксируется в начале шага; по умолчанию порядок возрастающий. Необязательный `order` задаёт список различных существующих ID, который копируется до исполнения; биологический слой передаёт перемешанный список организмов. Вложенный `step` запрещён. Если обработчик выбросил исключение, оно передаётся вызывающему коду, tick не увеличивается, уже выполненные изменения не откатываются. Это синхронный каркас для корректных обработчиков, без многопоточного доступа и транзакционного отката тика.

Случайные выборы выполняются через `world.rng`. Воспроизводимость проверена для одинаковых seed и операций в одной версии реализации; между версиями Python не гарантируется.

## Управляющая VM

[core/vm.py](core/vm.py): `execute(genome, sensors=..., perform=..., rng=...)` проверяет ленту 32×0–31 без bool и возвращает `ExecutionResult(instructions_executed, reason, last_pc)`. Причины завершения: `terminal_action` или `budget_exhausted`; last_pc — адрес последней исполненной инструкции, а не следующей. Вызов всегда начинает с PC=0 и бюджетом 16, памяти нет.

`sensors.front()` возвращает целую категорию 0–5, `sensors.hungry()` — bool. `perform(Action)` возвращает bool успеха. False у терминального действия заканчивает вызов; исключения адаптеров передаются вызывающему коду без отката их эффектов. Случайный переход использует переданный RNG; TURN_RANDOM только вызывает исполнителя, реальный выбор направления добавлен в биологическом адаптере 003. VM не зависит от World/Entity и не изменяет геном.

`python3 -m core.vm_example` исполняет известную программу с подставными адаптерами: IF_FRONT → TURN_LEFT → MOVE (отказ). Результат: 3 инструкции, `terminal_action`, последний PC=5. Полные правила — в [rules.md](docs/rules.md).

## Ресурсы и реальные действия

[core/biology.py](core/biology.py): `BiologicalWorld(width, height, seed=..., reserve=...)` владеет приватным техническим World и закрытым резервом. `create_organism(x, y, genome)` создаёт организм с 256 E / 64 M, ценой 512 из резерва; явные `energy`, `minerals`, `direction` служат настройке начального сценария. Геном копируется в неизменяемую ленту. `create_plant(..., profile='tree'/'bush'/'grass', energy=..., minerals=...)` и `create_remains(...)` создают минимальные ресурсные цели. Их ёмкости ещё не определены; запасы задаются явно и полностью оплачиваются резервом.

`get`, `get_at`, `entities` возвращают неизменяемые снимки. `remove` возвращает остаток E+4*M в резерв, `move` технически перемещает без затрат. `perform(id, Action)` выполняет игровое действие с принятой ценой. Публичной установки запасов/резерва нет. Нехватка резерва при создании вызывает `InsufficientReserveError`, некорректные данные — исключения, обычный отказ действия — False. Стоимость EAT списывается даже при отсутствии переноса; MOVE оплачивает либо успешный шаг, либо заблокированную попытку, если хватает энергии.

`RulesConfig` неизменяемо хранит утверждённые параметры; иной баланс пока отвергается. Бюджет `total_resources = reserve + Σ(E+4*M)` сохраняется: затраты возвращаются резерву, добыча берёт из него, питание переносит запасы, обе конверсии сохраняют эквивалент. Создание и удаление полностью учитываются. Обычные операции биологического слоя не открывают доступ к мутациям внутреннего World; низкоуровневый World отдельно не отвечает за ресурсы. Прямое изменение приватных полей не поддерживается.

`OrganismAdapter` предоставляет сенсоры и исполнитель независимой VM. `BiologicalWorld.step()` фиксирует организмы, перемешивает их RNG мира и вызывает VM не более одного раза на ID; возвращает пары ID/ExecutionResult в порядке ходов. Тот же `rng` используется действиями и VM, его `getstate()` доступен для проверок.

`python3 -m core.biology_example` выполняет пять тиков с добытчиком, ходящим организмом, потребителем, растением и останками. На каждом шаге R=4096. Размер, seed и бюджет примера — параметры демонстрации. Рост, метаболизм, смерть, распад, размножение и мутации отсутствуют: нулевые запасы не удаляют сущность, а длительный прогон пока не демонстрирует полноценную эволюцию. Исключение во время тика не откатывает предыдущие действия и состояние RNG; многопоточный доступ не предусмотрен.
