# Cyberbiology 2.0

Локальная лаборатория эволюции программируемых организмов. Главный приоритет — изучение архитектуры и разработки с Codex. Проект переписывается с нуля; `legacy/` и исходный аудит сохраняются без изменений.

Завершены задачи 001–004, 006 и 007 (объём 005 выполнен в 004): технический мир, независимая VM, ресурсные действия и жизненный цикл с растениями, рождениями, происхождением и мутациями. F01–F10 выполнены. Добавлены CLI воспроизводимых экспериментов и диагностика смертей. API, интерфейс и сохранения ещё не созданы. Используется установленный Python 3.13.0 и стандартная библиотека, включая unittest; зависимости не устанавливались.

Из корня проекта, без установки:

```sh
python3 --version
python3 -m unittest discover -s tests -v
python3 -m core
python3 -m core.vm_example
python3 -m core.biology_example
python3 -m core.lifecycle_example
python3 -m core.lifecycle_example --long
python3 -m core.runtime_example
git diff --check
```

Проверено: 110 тестов, OK. Прежние примеры работают с текущими правилами; ресурсный пример выполняет пять тиков с R=4096. Новый пример — 140 тиков с известным геномом PHOTOSYNTHESIS и всеми тремя растениями, выводом метрик и проверкой R=30000 на каждом шаге. Параметры этого сценария — примеры, не новые правила баланса.

`--long` выполняет два одинаковых прогона по 2000 тиков и сравнивает сущности, резерв, tick, следующий ID, события и состояние RNG. Фактический итог: резерв 0, R=30000; 1 рождение и 2 смерти организмов, 800 рождений и 760 смертей растений, 0 мутаций. Остались 43 grass и 2 останков, организмы вымерли. Это проверка воспроизводимости и бюджета; устойчивую эволюцию или качество баланса один сценарий не доказывает.

## Технический мир и VM

[World](core/world.py) управляет координатами и уникальными ID, не знает ресурсов. `get_at` возвращает None для пустоты и вызывает OutOfBoundsError за краем; `get(id)` возвращает None для отсутствующего ID. Размещение в занятую клетку запрещено (OccupiedCellError), изменение отсутствующего ID — UnknownEntityError. Типы/размеры валидируются. Ошибочные операции не меняют состояние, следующий ID или RNG. Техническое перемещение в собственную клетку разрешено.

`World.step(update=None, order=None)` сохраняет возрастающий порядок по умолчанию; явный order копируется и проверяется на уникальные существующие ID. `World.run_tick(callback)` даёт общую границу составного тика. Вложенные тики запрещены; успешное завершение увеличивает tick один раз. Исключение не откатывает уже выполненные эффекты и не увеличивает tick.

[VM](core/vm.py) принимает геном 32×0–31 без bool, сенсоры, исполнитель и RNG. Каждый вызов начинается с PC=0, бюджетом 16 и без памяти. Полная валидация предшествует эффектам; VM не изменяет геном. Результат: `ExecutionResult(instructions_executed, reason, last_pc)` — последний исполненный адрес. Причины: terminal_action, budget_exhausted, adapter_stopped.

Необязательный `is_active` проверяется после каждого действия; False останавливает VM до следующей инструкции и до обычного терминального завершения. При ручном подключении `OrganismAdapter` передавать `is_active=adapter.is_active`; BiologicalWorld.step делает это автоматически. Сенсоры возвращают целую категорию 0–5 и bool голода; исполнитель — bool. Исключения адаптеров/callback передаются вызывающему коду, не означают смерть или отказ. Без callback контракт 002 сохранён.

## Биологический слой

[BiologicalWorld](core/biology.py) владеет приватным World, резервом и неизменяемыми ресурсными снимками. Публичной установки запасов или возраста нет. `create_organism` по умолчанию создаёт возраст 0, север, 256 E / 64 M за 512 из резерва; явные начальные запасы валидируются. `create_plant` требует явных запасов в пределах профиля tree/bush/grass. `create_remains` не обрезает запасы. Нехватка резерва — InsufficientReserveError без частичных изменений. Снимки не обновляются автоматически: актуальные записи читать по ID.

`remove` — техническое удаление с возвратом остатка в резерв, без события смерти; `move` — техническое перемещение без цены. `perform` выполняет игровое действие. При смертельной оплате дальнейших эффектов нет: EAT при E=1 не получает ресурс цели. Смерть меняет живой ID на новый ID останков в той же клетке, без возврата ресурсов в резерв; оба нулевых запаса освобождают клетку. Пустые съеденные останки удаляются сразу.

Бюджет R = резерв + Σ(E+4*M) сохраняется при создании, действиях, росте, делении запасов при рождении, смерти и распаде. Последний возвращает остаток в резерв. Обычные операции биологического слоя не открывают обход учёта через внутренний World; прямое изменение приватных полей не поддерживается.

`step` фиксирует все три списка участников: останки по ID → перемешанные растения → перемешанные организмы. Каждая живая фаза перемешивается непосредственно перед выполнением; растения растут до ходов организмов. Возраст растёт один раз, смерть проверяется в установленных фазах и после действий. Дети и новые останки ждут следующего тика. Возвращаются ID/ExecutionResult только организмов, дошедших до VM.

`RulesConfig` хранит принятые параметры и вложенные PlantRules. Для проверок допускаются уменьшенные пределы возраста и вероятности mutation_percent / plant_reproduction_percent от 0 до 100; иной баланс пока отвергается. Весь геном наследуется независимо; мутация при рождении меняет одну любую ячейку. parent_id/founder_id/generation отражают происхождение, а сенсор родства по-прежнему сравнивает геномы.

`metrics` возвращает снимок событий (рождения/смерти организмов и растений, мутации) и численности organisms/tree/bush/grass/remains. Ручное создание не считается рождением. CLI ниже выбирает готовый сценарий и seed; произвольные пользовательские сценарии и изменение баланса через CLI пока не предоставляются. Нет многопоточного доступа, отката неуспешного тика, API/UI или сохранений.

## CLI экспериментов (006)

Все параметры обязательны: целочисленный `--seed`, `--scenario` из четырёх имён, неотрицательный `--ticks`, положительный `--interval`, `--output` в существующей папке. Ноль тиков допустим: отчёт содержит одну начальную/финальную запись. CLI выполняет весь запрошенный период после исчезновения организмов. Биологические параметры по умолчанию сохранены.

Реально выполненные команды сравнения на Python 3.13.0:

```sh
mkdir -p /tmp/cyberbiology-006
python3 -m core.experiment --seed 42 --scenario nop --ticks 2000 --interval 100 --output /tmp/cyberbiology-006/nop.json
python3 -m core.experiment --seed 42 --scenario photosynthesis --ticks 2000 --interval 100 --output /tmp/cyberbiology-006/photosynthesis.json
python3 -m core.experiment --seed 42 --scenario branching --ticks 2000 --interval 100 --output /tmp/cyberbiology-006/branching.json
python3 -m core.experiment --seed 42 --scenario mixed --ticks 2000 --interval 100 --output /tmp/cyberbiology-006/mixed.json
python3 -m core.experiment --seed 42 --scenario mixed --ticks 2000 --interval 1 --output /tmp/cyberbiology-006/mixed-detailed.json
```

Начальные условия в [scenarios.py](core/scenarios.py), полная лента и размещение также включаются в JSON. Указанные размеры, бюджеты и запасы — параметры сценариев, не новые правила. Все организмы начинают с севера.

| Сценарий | Начальные условия | Ожидаемое поведение |
|---|---|---|
| nop | 7×3, R=1000; (3,1), E=20/M=64, 32 нуля | Контроль расхода 1 E за ход без добычи |
| photosynthesis | 7×3, R=5000; (3,1), E=256/M=64; [6] и 31 ноль | Добыча только из резерва, возможное рождение при порогах |
| branching | 7×3, R=5000; (3,1), E=256/M=64; [10,3,4,8,6] и 27 нулей | IF_HUNGRY: сытый → адрес 3, ENERGY_TO_MINERALS; голодный → адрес 4, PHOTOSYNTHESIS. Ёмкость минералов ограничивает конверсию |
| mixed | 17×11, R=30000; организм (8,5), E=900/M=100, PHOTOSYNTHESIS; tree (1,1), 1500/1500; bush (5,1), 750/750; grass (12,1), 190/190 | Прежний сценарий 004: растения и организмы конкурируют за закрытый резерв |

Ни один сценарий не обещает выживания. Результаты для seed=42, 2000 тиков:

| Сценарий | Исчез последний организм | Рождения организмов | Мутации | Наибольшее наблюдавшееся поколение | Смерть организмов |
|---|---:|---:|---:|---:|---|
| nop | 20 | 0 | 0 | 0 | Исчерпание E, метаболизм |
| photosynthesis | 172 | 1 | 0 | 1 | Предел возраста, начало хода |
| branching | 128 | 0 | 0 | 0 | Предел возраста, начало хода |
| mixed | 158 | 1 | 0 | 1 | Предел возраста, начало хода |

В mixed рождение произошло в тик 30. Родитель умер в тик 128, потомок — 158; обоим было 128, оба имели E=1024/M=50. Минералы после деления ниже порога рождения 52, а эта программа их не добывает. Поэтому отсутствие дальнейших поколений объясняется её запасами и поведением; непосредственная причина обеих смертей — возраст, а не нехватка E. Все 760 смертей растений также были по возрасту на начале хода. К тик 2000: 800 рождений растений, 43 grass и 2 останков, резерв 0, R=30000.

В NOP расход подтверждён контрольным примером. Фотосинтез дал одного потомка, но не устранил ограничение возраста/минералов. Ветвление переключает добычу и минерализацию; в этом опыте пороги рождения не достигнуты. Выводы относятся к данным фиксированных сценариев: они не доказывают устойчивую эволюцию, общую оптимальность программы, качество баланса или ускорение реализации. Автоматического подбора и исправления правил ради выживания нет.

## Формат и диагностика

[experiment.py](core/experiment.py) записывает `report_version=1`, `rules_version=004-v1` (биологический контракт 004), версию Python, seed, полную конфигурацию мира/правил/VM и исходный сценарий. Есть requested_ticks/executed_ticks, metrics_interval, history и final. История содержит tick=0, каждый интервал и финал ровно один раз; финальная запись отдельно доступна как final. Каждая метрика включает численности, резерв/R, накопленные события и max_generation живых, либо null.

Инварианты проверяются на каждом тике независимо от интервала. organism_extinction_tick тоже определяется каждый тик, поэтому не округляется до интервала истории. max_generation_observed — максимум среди живых в tick=0 и на концах всех выполненных тиков, а не только записанных интервалах; это не журнал каждого рождения внутри тика.

`BiologicalWorld(..., record_deaths=True)` сохраняет неизменяемые DeathRecord в момент смерти до замены ID: tick, entity_id, тип/профиль, возраст/предел, E/M, все истинные reasons и отдельный context. Контексты: turn_start, metabolism, own_action, other_feeding. Внутри шага событие имеет номер завершаемого тика; при прямом действии вне шага — текущий tick. Распад останков и техническое удаление не добавляют смерть. По умолчанию диагностика выключена; CLI её включает.

JSON содержит записи смертей и суммы признаков/контекстов. Несколько признаков одной смерти учитываются одновременно, поэтому сумма признаков может превышать число смертей. Причины не восстанавливаются по итоговым останкам. Тесты подтверждают одинаковые игровые состояния и RNG при отключении отчёта/диагностики и смене интервала. Запись JSON также не расходует RNG.

Отчёт — результат опыта, без состояния RNG и полного мира для продолжения. Нет восстановления, API/UI, графиков или трассировки инструкций. История и записи смертей хранятся в памяти до записи JSON; их объём растёт с длительностью опыта и частотой наблюдения. Файл записывается через временный файл и атомарную замену; прежний файл по указанному пути заменяется. Коммит не создаётся автоматически.

## Синхронный runtime (007)

[SimulationRuntime](core/runtime.py) создаётся с явными `scenario`, `seed`, `config=RulesConfig()`, владеет одним приватным миром и начинает в paused. `start()` переводит в running, `pause()` — в paused; повторные команды безопасны. start не запускает таймер, поток или цикл. `step()` делает один тик только на паузе, `advance()` — один тик только в running. Внешний код решает, когда вызвать advance.

`reset(scenario=..., seed=..., config=...)` полностью готовит новый мир до замены, возвращает paused, сбрасывает события и ошибку. Каждому миру назначается новый UUID run_id, без RNG мира. Все методы управления и чтения принимают необязательный `expected_run_id`; старый ID вызывает StaleRunError до эффектов. Ошибка состояния — RuntimeStateError, вложенная команда/чтение — NestedCommandError. Невалидный reset сохраняет старый мир и статус, включая failed.

`status()`, `field_snapshot()` и `entity_details(id)` возвращают отделённые словари/списки. Чтение и изменение этих данных не меняют мир/RNG. В поле только размеры, ID, координаты, тип, профиль и направление; геномы передаются только в деталях сущности, вместе с возрастом, запасами и происхождением. Отсутствующая сущность даёт entity=None. Снимки содержат status/run_id/tick, метрики, R, initial_budget, completed и last_completed_tick. Это не формат сохранения.

Исключение тика передаётся вызывающему коду, переводит runtime в failed и сохраняет тип/сообщение ошибки, команду и attempted_tick. В failed start/step/advance запрещены; pause сохраняет failed. Только успешный reset восстанавливает работу. Отката частичного состояния нет: completed=False явно запрещает считать такой снимок завершённым, а last_completed_tick остаётся последним успешным. Метрики и детали failed показывают диагностическое частичное состояние. Вложенные чтения во время команды также запрещены; конкурентный доступ не поддерживается.

Реально выполнено на Python 3.13.0:

```sh
python3 -m unittest discover -s tests -q
python3 -m core.runtime_example
git diff --check
```

110 тестов, OK (12 новых проверок runtime и 98 прежних). Пример: paused/tick=0 → step → start → 3 advance → pause/tick=4, R=30000 → детали организма → reset/paused/tick=0 с новым run_id. Биологические правила не изменены; API, процессы и транспорт не реализованы.

Минимальная будущая граница процесса: один процесс владеет этим runtime; получает имя команды, аргументы и expected_run_id, возвращает результат/ошибку с run_id, статусом и границей тика. Поле и детали запрашиваются отдельно. Периодический вызов advance и доставка команд находятся снаружи runtime; формат очереди, подтверждения и транспорт выбираются в следующей задаче. Мир и RNG через границу не передаются.
