# Правила симуляции

## Статус и приоритет

Этот документ фиксирует принятые пользователем решения отдельно от предложений. Аудит описывает старый код и кандидатов на правила; его числа, таблица VM и этапы не становятся требованиями автоматически. [ADR 0001](decisions/0001-reactive-genome.md) уточняет принятое решение о геноме. Контракт задачи 001 принят для каркаса мира и не утверждает биологические механики.

## Принятые решения

- Переписывание с нуля с сохранением основной идеи. Старый код — источник механик, а не эталон правильного поведения.
- Только локальное развёртывание; приоритет — обучение архитектуре и разработке с Codex.
- Планируем Python для ядра и backend, отдельный веб-интерфейс. Конкретный стек и версии остаются предложениями.
- Ресурсный бюджет закрыт: внешнего притока нет. Энергия и минералы переходят между резервом и сущностями и конвертируются по установленным правилам. Формула эквивалента, единицы и коэффициенты пока не приняты. Нельзя вводить бесплатный приток под названием фотосинтеза.
- Первая версия включает дерево, куст и траву. Предпочтительна одна модель растения с разными параметрами; конкретные параметры не приняты.
- Каждый ход VM начинает с ячейки генома 0; указатель между ходами не сохраняется.
- Наследуется весь геном, включая неисполняемые участки. Мутация может затронуть любую ячейку. Автоматического удаления неиспользуемых участков нет.
- Геном потомка независим от генома родителя: изменение одного не меняет другой.
- Исполнение ограничено бюджетом инструкций; завершающее действие заканчивает ход. Размер бюджета, цены и перечень завершающих действий ещё не определены.
- Новый набор инструкций из аудита не утверждён.

## Принято: мир и тик итерации 001

Мир — конечная прямоугольная сетка с положительными целочисленными размерами и координатами `(x, y)`. Одна сущность на клетку. Выход за границы запрещён и явно отличается от пустой клетки; переноса на противоположный край нет.

У каждой сущности уникальный целочисленный ID, стабильный при перемещении и не переиспользуемый в пределах мира. В начале тика фиксируется список существующих ID в возрастающем порядке. Каждый ID обновляется не более одного раза; перед вызовом проверяется его существование. Созданные во время тика сущности впервые обновляются в следующем тике. Изменения последовательны; tick увеличивается ровно один раз после завершения шага.

Возрастающий порядок ID — временное решение итерации 001. Перед питанием и размножением нужно пересмотреть порядок конкурентных действий: преимущество ранних ID не должно остаться неосознанным правилом.

Все случайные операции используют отдельный RNG мира с seed. Воспроизводимость проверяется при одинаковых seed, операциях и версии реализации; равенство между разными версиями Python не обещается. В итерации 001 используются доступный Python 3.13.0, стандартная библиотека и `unittest`, без установки пакетов.

Ошибочные операции размещения, удаления и перемещения не меняют мир, следующий ID и RNG. Конкретный контракт ошибок и чтения описан в [задаче 001](tasks/001-headless-world.md). Биологические фазы не приняты.

## Предложения: ресурсы и жизненный цикл

Кандидат из аудита: целочисленные ресурсы и эквивалент `R = резерв + Σ(E + k·M)` для всех сущностей, включая останки; `k = 4` — только кандидат. Расходы возвращаются резерву, питание переносит ресурсы, размножение делит их, распад возвращает остаток. Создание сущностей в текущем опыте оплачивается из резерва; reset начинает новый опыт с новым начальным бюджетом.

Кандидаты: ограниченные ёмкости; отказ при нехватке ресурса; отдельная стоимость попытки и успешного действия; конечный поиск свободной клетки; автоматическое размножение; смерть и останки. Ни пороги, ни стоимость метаболизма, ни деление ресурсов, ни вероятность мутации, ни срок распада не утверждены. Числа старого проекта не использовать как значения по умолчанию без решения.

Единая модель растения с профилями дерева, куста и травы предпочтительна. Различия роста, вместимости, возраста и распространения требуют таблицы параметров. Все три профиля должны войти в первую версию.

## Предложения: VM и её сокращение

| Группа | Рекомендация, пока не решение | Последствие для поведения |
|---|---|---|
| MOVE, EAT, PHOTOSYNTHESIS | Сохранить смысл шага, питания и получения энергии из резерва | Пространственная конкуренция, потребление и добыча остаются базовыми стратегиями; при пустом резерве добыча ограничена |
| MINERALS_TO_ENERGY, ENERGY_TO_MINERALS | Сохранить обе конверсии с явно принятой ресурсной формулой | Возможен выбор формы запасов; обратимость и цены определят выгодность циклов |
| Старые повороты 3/4 | Заменить явными TURN_LEFT/RIGHT | Убирается зависимость от неоднозначной временной памяти; программы проще объяснять |
| Случайное направление | Сохранить TURN_RANDOM через RNG мира | Сохраняется случайное исследование пространства и воспроизводимость |
| Проверка впереди и голода | Сохранить IF_FRONT/IF_HUNGRY; голод вычислять по текущим ресурсам | Реакция на окружение и запасы вместо «вечного голода»; категории и порог ещё нужны |
| NOP и переходы | Предусмотреть NOP и явно описанные переходы; JUMP_RANDOM оставить кандидатом | Нейтральные участки и случайный выбор ветвей возможны; формат и адресация определят достижимость участков |
| Самомутация (старый 0) | Отложить; сначала мутация при наследовании | Проще отделить наследуемую изменчивость от намеренного изменения программы; исчезает стратегия самомутации |
| Память направления атаки и ветвление по атакам (11/12) | Отложить до определения событий и памяти | Реакция на прошлую атаку пока недоступна; сенсор окружения остаётся |
| Продление жизни (13) | Отложить до жизненного цикла и баланса | Нет покупки возраста и соответствующей стратегии долголетия |
| Сон | Отложить отдельную механику; не кодировать его направлением | Нет долговременного энергосберегающего состояния; его экономику нужно определить отдельно |

Нумерацию старых кодов не переносить автоматически. Аудит предлагает ленту из 32 ячеек со значениями 0–31, бюджет 16, кольцевые чтения, соседние ячейки как операнды и завершение даже неудачной терминальной попытки. Всё это остаётся предложением, включая отсутствие памяти между ходами: принят только сброс указателя, а не запрет любой памяти.

Неисполняемая ячейка может читаться как операнд или стать исполняемой после мутации перехода. Нейтральность зависит от программы и окружения, не даёт права удалять ячейку.
