# Задача 007: синхронный runtime

Статус: **done**. Контракт принят пользователем.

Вход: [AGENTS](../../AGENTS.md), [правила](../rules.md), [архитектура](../architecture.md), [roadmap](../roadmap.md), [эксперименты](../../core/experiment.py).

## Объём и контракт

Один приватный BiologicalWorld. Начальное состояние paused; start/pause идемпотентны. start не запускает вычисление или таймер. step разрешён только в paused, advance — только в running; каждый выполняет один тик. reset требует явные сценарий, seed и RulesConfig: новый мир полностью строится до замены, возвращает paused и сбрасывает события/ошибку. Новый run_id — UUID из стандартной библиотеки, без RNG мира.

Все методы принимают необязательный expected_run_id: несовпадение отвергается до эффектов, включая reset. Вложенные команды и чтение во время команды запрещены; конкурентный доступ не поддерживается. Ошибки параметров/состояния не являются отказом тика.

Исключение при выполнении тика передаётся вызывающему коду; runtime становится failed, сохраняет тип/сообщение ошибки, команду и номер попытки. start/step/advance блокируются; pause в failed не снимает ошибку. Только успешный reset восстанавливает paused. Частичное состояние не откатывается. Снимок failed помечен completed=False, last_completed_tick остаётся последним успешно завершённым тиком.

Публичный статус, компактный снимок и подробности сущности — независимые данные без ссылок на изменяемый мир. Поле содержит размеры, ID/координаты/тип/профиль/направление без геномов. Детали по ID включают запасы, возраст, геном и происхождение. Статус/снимки содержат run_id, tick, сведения об ошибке, завершённость, метрики и баланс. Нет сохранения, API/UI, потоков, процессов, async, таймеров или очередей.

## Приёмка

- R01: начальная пауза, повторные start/pause без тиков и расхода RNG.
- R02: step/advance доступны только в нужном состоянии и выполняют один тик.
- R03: reset воспроизводит стартовый сценарий с новыми ID опыта, сбрасывает метрики/ошибку; неверный reset сохраняет прежние мир/статус/RNG.
- R04: устаревший run_id отвергается до эффектов для всех методов, включая reset и чтение.
- R05: снимки/детали независимы от дальнейшего мира; их изменения не меняют мир. Геномов в поле нет; наблюдение не расходует RNG и не влияет на результат.
- R06: вложенные команды отвергаются; искусственная ошибка после частичного изменения даёт failed без отката, блокирует продолжение, допускает только успешный reset. failed нельзя представить завершённым тиком.
- R07: весь unittest и пример create→step→start→advance→pause→read→reset проходят; git diff --check без ошибок.

Коммит не создавать. F10 завершать только в синхронном объёме; API/очереди/дедупликация команд не считаются реализованными.

## Фактическая приёмка

[Реализация](../../core/runtime.py), [12 тестов](../../tests/test_runtime.py), [пример](../../core/runtime_example.py). Проверены R01–R06, в том числе невалидное размещение при подготовке reset и ошибка после изменения мира/после продвижения его счётчика. last_completed_tick и completed отличают failed от успешной границы. В тестах внутренний RNG читается только для проверки; публичный runtime его не выдаёт.

`python3 -m unittest discover -s tests -q`: 110 тестов, OK на Python 3.13.0. `python3 -m core.runtime_example`: начальная пауза, один step + три advance дают tick=4 и R=30000; reset возвращает tick=0/paused с новым UUID. `git diff --check`: без ошибок. Биология и зависимости не изменены; коммит не создан.

F10 завершена в синхронном объёме. F11–F12 остаются planned. Предлагаемая следующая граница процесса — явные команды/аргументы/expected_run_id и отделённые ответы/ошибки, поле без геномов и детали по ID. Процесс владеет runtime; транспорт не владеет миром. Формат доставки и управление частотой advance требуют отдельной задачи.
