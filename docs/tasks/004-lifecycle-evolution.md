# Задача 004: жизненный цикл и наследуемые мутации

Статус: **done**. Контракт пользователя принят в [rules.md](../rules.md), [ADR 0004](../decisions/0004-lifecycle.md).

Вход: правила, [архитектура](../architecture.md), [реестр](../features.md), результаты задач [001](001-headless-world.md), [002](002-genome-vm.md), [003](003-organism-actions.md).

## Объём

Возраст, метаболизм и смерть; три профиля роста и расселения растений; рождения с делением ресурсов; полная лента и мутация одной ячейки; происхождение; распад и немедленное удаление пустых останков; минимальные счётчики. Одна общая граница тика, неизменяемые снимки и закрытый бюджет.

Нет API/UI, сохранений, новых зависимостей, оптимизаций или изменения legacy. Технические создание/удаление не считаются рождением/смертью. Создание живой сущности с нулевыми запасами допустимо для настройки, но первая проверка жизнеспособности её убивает; исполнение действий её не оживляет. Изначально пустые технические останки удаляются при обработке, а полностью съеденные — немедленно.

## Приёмка

- L01: останки → растения → организмы; списки фиксируются заранее, shuffle каждой живой фазы выполняется непосредственно перед ней; tick +1 один раз.
- L02: возраст один раз, смерть до VM по возрасту/ресурсам/метаболизму; погибший исполнитель не продолжает VM, погибшая жертва пропускается.
- L03: оплата EAT при E=1 приводит к смерти без переноса; остальные смертельные оплаты не выполняют дальнейших эффектов.
- L04: смерть сохраняет E+4*M, меняет ID; новые останки возраст 0, распад после 10 последующих тиков; съеденные пустые останки удаляются.
- L05: пороги и отсутствие места; нечётное деление; независимая полная лента/направление; parent/founder/generation; мутация ровно одной ячейки, 0%/100% без статистических тестов.
- L06: профили tree/bush/grass, порядок E→M, частичный резерв/ёмкости, пороги и шанс растений; дети ждут следующего тика.
- L07: счётчики/воспроизводимость; бюджет и неотрицательность после каждой операции и полного шага.
- L08: весь unittest, ограниченные примеры, длительный воспроизводимый headless-прогон и git diff --check.

Прежние тесты изменять только при явной смене контракта: M=0/E=0 больше не жизнеспособны, EAT не спасает E=1; шаг включает метаболизм/рост/смерть. Сохранять тесты цен, границ, валидации, RNG и баланса. Завершать функции строго по приёмке, коммит не создавать.

## Фактическая приёмка

Реализация: [biology](../../core/biology.py), [VM](../../core/vm.py), [World](../../core/world.py). [25 проверок 004](../../tests/test_lifecycle.py), [прежние проверки действий](../../tests/test_biology.py) и [проверки callback VM](../../tests/test_vm.py) покрывают L01–L07. Неисполняемая ячейка 31 проверена как наследуемая и доступная мутации; шанс 0/100% проверяется детерминированно. Техническая приёмка World.step сохранена.

На Python 3.13.0 `python3 -m unittest discover -s tests -v` — 80 тестов, OK. Все примеры (`core`, `core.vm_example`, `core.biology_example`, `core.lifecycle_example`) проходят. `python3 -m core.lifecycle_example --long` — два одинаковых прогона по 2000 тиков совпали по сущностям, резерву, tick/ID, метрикам и RNG; на каждом тике R=30000 и ресурсы неотрицательны. `git diff --check` — без ошибок.

Итог длинного сценария: резерв 0; 1 рождение и 2 смерти организмов; 800 рождений и 760 смертей растений; 0 мутаций. Остались 43 grass и 2 останков, организмы вымерли. Изменений правил ради выживания не было. Сценарий не доказывает устойчивую эволюцию.
