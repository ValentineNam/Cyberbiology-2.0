# Задача 001: независимое ядро мира

Статус: **done**. Контракт принят пользователем; A01–A09 выполнены.

## Цель и входные документы

Создать минимальное ядро, на котором можно проверять размещение и планирование независимо от биологических механик, API и браузера. Читать [product](../product.md), [rules](../rules.md), [architecture](../architecture.md), [features](../features.md) и [ADR 0001](../decisions/0001-reactive-genome.md).

Контракт принят. Используются доступный Python 3.13.0, стандартная библиотека и `unittest`; установки не требуются. Открытые вопросы VM и экономики не блокируют эту задачу.

## Принятый контракт задачи

- Размеры — положительные целые ширина и высота, координаты `(x, y)` с нуля. Прямоугольный мир конечен, без тороидального переноса и обязательного кольца стен. Одна сущность на клетку.
- Чтение за границей явно отличается от пустой клетки. Размещение и движение за границу или на занятую клетку отвергаются без частичного изменения.
- Сущности пока технические записи с ID и координатами, без генома, энергии и биологического типа. ID уникальны, стабильны при перемещении, не используются повторно в одном мире; порядок ID определён и воспроизводим. ID — целое число; структура хранения — выбор реализации.
- Добавление, удаление и перемещение согласованно меняют сетку и реестр; удалённый ID больше не занимает клетку. Отказная операция не меняет мир, счётчик ID и RNG. Ошибки сообщаются исключениями: `TypeError` для неверного типа (включая bool вместо int), `ValueError` для неположительного размера, `OutOfBoundsError` для внешней координаты, `OccupiedCellError` для занятой клетки, `UnknownEntityError` для отсутствующего ID. Чтение допустимой пустой клетки возвращает `None`. Движение в собственную клетку — успешная операция без изменения. Чтение по ID возвращает сущность либо `None`; удаление отсутствующего ID — ошибка.
- Мир владеет отдельным RNG, инициализированным явным seed. Случайность каркаса/тестового сценария не использует глобальный RNG и часы. Не обещать равенства потоков между разными версиями Python.
- `step` фиксирует начальные ID в возрастающем порядке ID, последовательно вызывает предоставленный обработчик для каждого ещё существующего ID не более одного раза и увеличивает tick на один после успешного завершения. Перемещение не даёт повторного хода. Новые ID обновляются со следующего тика, удалённые пропускаются. Обработчик может менять мир через его операции, но не вызывать вложенный `step`.
- Пустой мир также допускает шаг. Обработчик по умолчанию ничего не делает. Ошибки внутри пользовательского обработчика и транзакционный откат тика не входят в приёмку: этот технический механизм используется только с корректными тестовыми обработчиками, без исполнения пользовательского кода.

Возрастающий порядок ID временный для 001: пересмотреть его перед питанием и размножением. Биологические фазы сюда не включены.

## Объём

Модель мира, координаты/границы, согласованный реестр и сетка, операции над техническими сущностями, RNG с seed, tick и синхронный `step`, проверки и краткая инструкция их запуска. Каталог реализации — `core/`, проверок — `tests/`; минимальный запуск — `python3 -m core`.

Не входят: VM, ресурсы, растения, старение/размножение/смерть, метрики популяций, таймеры, runtime play/pause, API, frontend, сохранение/загрузка, установка фреймворков, изменение `legacy/`. Перемещение записи — проверка структуры мира, а не инструкция MOVE и не платное действие организма.

## Проверяемая приёмка

| ID | Проверка | Ожидаемый результат |
|---|---|---|
| A01 | Создать поле 17×11; обратиться к углам, внутренней клетке и координатам -1, x=17, y=11; проверить также 1×1 | Правильные размеры; края доступны; внешняя координата отличима от пустой; нет переноса |
| A02 | Передать нулевой, отрицательный или нецелый размер | Понятный отказ до создания частичного мира |
| A03 | Добавить две записи, переместить первую, удалить вторую и добавить новую | ID уникальны и не переиспользуются; ID перемещённой записи сохранён; сетка и реестр согласованы после каждой операции |
| A04 | Попытаться разместить/переместить за край и в занятую клетку | Отказ; прежнее состояние, RNG и следующий ID сохранены |
| A05 | Выполнить одинаковый ограниченный сценарий операций и выборов через RNG в двух мирах с одинаковым seed | Совпадают журнал выборов, ID, координаты и tick; не требовать, чтобы любые разные seed обязательно дали разный итог |
| A06 | Выполнить дополнительные случайные выборы в одном из миров | Поток другого мира не меняется; независимость RNG подтверждена |
| A07 | Шаг пустого мира и несколько шагов с обработчиком без изменений | tick увеличивается на один за шаг; журнал содержит каждый существующий ID один раз в возрастающем порядке ID |
| A08 | В ходе первого ID переместить его в другую клетку, удалить ещё не обновлённый ID и добавить новый | Перемещённый не обновляется повторно; удалённый пропущен; новый отсутствует в журнале этого шага и появляется в следующем |
| A09 | Запустить проверки ядра без API, браузера и сторонних runtime-зависимостей | Проверки проходят; импорты ядра не требуют транспорта/UI; команда запуска документирована и реально выполнена |

Размер 17×11 — тестовый пример, не настройка симуляции. Состояние для сравнения можно получать через публичное чтение мира; формат сериализации не требуется. Сценарии A05–A08 ограничены числом операций и не используют вероятностных утверждений.
